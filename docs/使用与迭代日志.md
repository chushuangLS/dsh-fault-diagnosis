# 使用与迭代日志

> 记录日常运维使用中发现的问题、灵感，以及对应的改动。

这份日志的作用是把「真实使用」和「代码演进」连起来：
往下翻能看到项目不是一次性做完的，而是**每天在用的过程中发现问题、再改**。
参赛材料里的「解题有效性」和「开发过程可复现」都可以引它作为佐证。

## 项目时间线

- **2026-10-15 ~ 10-16**：从零完成核心功能与工程化建设
  （v0.1.0 → v0.10.0，共 8 个迭代：知识库 → 接入大模型 → 对话式排查 →
  Web 界面 → 设备台账与报修闭环 → 检索增强与自动沉淀 → 数据分离与并发保护 →
  自动化测试与 CI → 报表与界面重构）
- **2026-10-17 起**：进入**持续使用与迭代**阶段，根据实际运维中发现的问题逐步完善

## 怎么记

**新发现的问题写进下面的「待处理」区**，我按那里的内容动手；
处理完会把它挪到当天的日期条目里，并填上对应的 commit。

写的时候说清「看到什么现象」+「期望怎样」就够了，
不用自己分析原因 —— 定位问题我来做。

## 2026-10-17

**使用情况**

- 用真实故障跑了几轮诊断：总闸跳闸、教室没电、教室断网、空调故障
- 导入了第一实验楼 C104 的场地课表（78 条课程）

**发现的问题**

1. **教室级设施故障被算成"电脑损坏"**
   总闸跳闸、交换机故障这类教室设备问题，只能按「电脑损坏」记录，
   于是显示成"损坏 80 台电脑"—— 电脑其实一台都没坏，坏的是配电箱。
   应该单独列一类。
2. **报表缺少损坏时间**
   只有"损坏几台"，看不出这个问题是什么时候出现的。
3. **⚠ 安全提示错误：让学生反复推闸**
   助手指引"把总闸推上去……"，
   而短路状态下反复合闸可能产生电弧甚至火灾。
   掉闸推一次不行就应该禁止学生再动。

   ![问题现场](screenshots/issue-breaker-chat.png)

   截图里 AI 连续两轮让学生推闸，最后还追问"有几台电脑出现这个情况" ——
   整间教室都断电了，问"几台"没有意义。
4. **看板图表点不了**
   看到"某状态有 N 条"或"某教室故障最多"之后，还得自己切到台账再筛一遍。
   希望饼图和柱状图能直接点进去。
5. **课表是下一个缺口**
   教室坏了，最急的不是"这台怎么修"，而是**"这节课去哪上"**。
   需要导入课表，才能知道现在哪间教室空着。

**改动**

- `feat`: 新增「故障对象」字段，分「电脑 / 教室设施」两类。
  设施故障不计入损坏台数，界面与报表单独标记（`8fc933d`）
- `feat`: Excel 报表在「损坏」后加「损坏时间」列，
  并新增「教室设施故障」列（`8fc933d`）
- `fix`: 提示词安全规则 —— 总闸只允许推一次，
  推上去还跳必须停手等电工；删除「总闸跳闸合闸即可」这条自修项（`8fc933d`）
- `fix`: 提示词的数量追问改为按故障范围区分，
  整间断电不再问"几台电脑"（`8fc933d`）
- `tools`: 新增 `migrate_facility_target.py`，
  把历史记录里 3 条设施故障重新归类（已备份原文件）
- `feat`: 数据看板图表可点击 ——
  饼图点某状态 → 跳到台账并筛好；柱状图点某教室 → 直接开详情（`01f2e10`）
- `feat`: 故障细分类（13 类部件 + 教室设施）与「反复故障」分析（`eb21a08`）
- `feat`: 课表导入、作息配置、空余教室查询、教师姓名脱敏（`9a9d73f`）
- `feat`: 运行总览取代数据看板 ——
  教室状态按「还能不能上课」判定、今日课程预警、调课去处建议

**踩过的坑**

- **分类器被诊断结论带偏**
  一开始把「故障现象 + 诊断结论」一起拿去做关键词匹配，
  结果结论里的鉴别诊断（"换线后显示器正常，问题在主机端"）
  把「电脑打不开」判成了显示故障 / 主板故障，18 条里错了 3 条。
  改成只按「故障现象」判才对 —— 现象是运维人员自己的简短描述，没有干扰。
- **课表里的斜杠**
  格子内容是「专业软件CAD/SU/(5-5节)1-8周/石嘉伟/…」，
  课程名和教学班名里都带斜杠，按 `/` 硬切会碎成 7 段。
  改用「(N-N节)X-Y周」当锚点，前后分别处理。
- **周次下拉框忘了填选项**
  查询参数 `week` 变成 `NaN`，接口返回 400，
  页面上看起来就是"点了没反应"。前端冒烟测试抓出来的 ——
  这类问题接口日志全绿、JS 也不报错，只靠看代码发现不了。

## 2026-10-18

**使用情况**

- 导入了全部 19 间教室的课表（1170 条课程）
- 教室台账按真实编号重建：第一实验楼 C4/C5/C6/C7/C8/C9 系列 + 第二实验楼

**发现的问题**

1. **教学楼下拉选不了东西**
   页面加载时填一次选项，之后改了教室结构就不更新。
   选到旧名字的教学楼，教室框就空着且点不动。
2. **运行总览「展开全部」把两栋楼位置对调**
   展开时把该楼栋挪到数组末尾再整份重渲染，顺序全乱。
3. **明天早八的课没有预警**
   两个原因叠加：
   - 预警只扫"今天"，今天周日没课 → 整块空白
   - 「交换机故障」不在影响上课的关键词里，整间断网判不出来
4. **课表页要自己点查询才能找课**
   选教学楼/教室/星期/节次再点查询，等于把找东西的活儿推回给使用者。
5. **列表越堆越长**
   报修记录、日常报备用久了就是几十条，一路往下滚很难找。

**改动**

- `fix`: 教学楼下拉改为每次进入页面/打开表单时重拉；
  选中的楼栋已被改名或删除时自动清空，不再留下"选不了"的空下拉
- `fix`: 运行总览的展开/收起改为按楼栋记状态，只改该楼栋显示几格，
  数组顺序不动
- `feat`: 预警范围扩到「今天 + 明天」，标题改「即将受影响的课」，
  每条标清「今天 周六」「明天 周一」
- `fix`: 新增「整间断网」判定 —— 故障对象是教室设施且提到交换机/上联时，
  算影响上课（机房课基本都要联网）
- `feat`: 课表页重做 —— 一屏摊开当天全部教室 × 节次，不用查询；
  点课程格子给调课建议（同层 → 座位接近 → 连续空闲多），
  点空格子看该节空闲教室；今天没课自动跳到下一个有课的日子
- `feat`: 所有列表统一分页，每页 10 条
- `feat`: 有「影响上课」级故障的教室整行染红，且不会被推荐为调课候选
- `fix`: 周次下拉在深色主题下白底白字看不见 —— 加 `color-scheme: dark`
- `chore`: 清理课表里的孤儿绑定（教室改名后遗留的 实验楼A|104）

**踩过的坑**

- 课表里「连堂」是两条独立记录（第 3-3 节、第 4-4 节），
  按单条记录的 `p_end - p + 1` 算连排会算成 1 节，
  挪过去课就断了。必须按「同一门课、同一老师连续排」往后数。
- 原生 `<select>` 只改收起状态的颜色不够，展开的选项列表用系统白底，
  文字颜色如果继承成浅色就会白底白字 —— 要 `color-scheme: dark`。

## 2026-10-20

**使用情况**

- 完整走了一遍日常使用：登记报修 → 看运行总览 → 点课中查课表 → 导出 Excel
- 提出"Web 每次都要先起服务再开浏览器，很不方便"，希望做成双击即用的软件

**发现的问题**

1. **导出的 Excel 在桌面窗口里没反应**
   浏览器里正常，窗口里点了什么都不发生。
2. **运行总览点「课中」打不开本周课表**
   弹窗一直停在"读取中…"。
3. **软件用着卡、掉帧**
4. **窗口缩不小**
   能最大化，但点还原没变化。

**改动**

- `feat`: 桌面窗口版 —— pywebview + 内嵌 WebView2，页面代码一行没改，
  只换启动方式；打开即最大化铺满屏幕
- `feat`: 打包成 exe（文件夹版），双击即用、不用装 Python
- `feat`: 设置改成侧边栏按钮 —— 查看/修改/清除 API Key、打开数据目录
- `fix`: 教学楼下拉缓存、运行总览展开换位、明天早八无预警（前一日遗留）
- `fix`: 课中课表打不开、作息设置空白（见"踩过的坑"）
- `fix`: 导出改为后端落盘 + 显示路径
- `fix`: 窗口还原尺寸、背景掉帧

**踩过的坑**

- **重写页面时删掉了别人还在用的变量。**
  重写课表页时把 `WEEKDAYS`、`schedSummary`、`PERIOD_SECTIONS` 删了，
  但"点课中查课表"和"作息设置"两处还在用。
  异常发生在给弹窗赋值之前，所以界面永远停在"读取中…"或一片空白 ——
  **看起来像卡死，实际是 JS 在渲染前就抛了**。
  修法不只是补变量：把渲染包进 `try/catch` 把错误显示出来，
  以后不会再无声地卡住。
- **打包后 __file__ 不是项目路径。**
  PyInstaller 会把自己解压到临时目录，`__file__` 指向那儿。
  数据写进去，程序一关就清空 —— 用户记的报修记录全没了。
  必须把"只读资源"和"可写数据"分开。
- **单文件 exe 起不来。**
  `[PYI-2580:ERROR] Could not create temporary directory!`
  单文件每次运行都要解压自己，这一步被杀软拦了，换临时目录也不行。
  改用文件夹版（onedir），没有解包步骤。
- **窗口里没有下载通道。**
  pywebview 的 winforms 后端没实现 WebView2 的 `DownloadStarting`，
  `a.click()` 触发的下载被静默丢弃 —— 所以导出"没反应"。
  改成后端直接写文件、界面显示路径。
- **画布不是画得慢，是合成慢。**
  实测背景每帧绘制只要 1.0 ms，但把它开到 60fps，
  整页帧率从 145–182 掉到 46–55。瓶颈是 DPR=2 时那块
  3414×2134 的画布层每秒要重新合成 60 次。
  降成 1 倍分辨率（面积 1/4）后恢复。
  **教训：为了省 CPU 把背景限到 20fps，其实是拿"一卡一卡"换了流畅 ——
  高刷屏上 20fps 的动画和 180fps 的界面放一起，用户感受就是掉帧。**
- **`backdrop-filter` 和动画背景是死敌。**
  全站 35 处背景模糊，静态背景看不出问题，一换成动画背景，
  这些区域每帧都要重新高斯模糊。改成半透明纯色后解决。
- **清 Key 清不掉。**
  删掉 config.json 里的 key，注册表兜底又把它找回来。
  改成写显式 `disabled` 标记，短路所有来源。
- **用正则批量改 CSS 会误伤。**
  `r'backdrop-filter:[^;]*;'` 也会匹配到 `-webkit-backdrop-filter`，
  把 `-webkit-` 前缀留下、吃掉换行，17 处声明的下一行被污染。
  浏览器对这种畸形声明是静默忽略的 —— 不报错、不崩，只是样式悄悄失效。
  现在有 `test_css_sanity.py` 兜着。
- **测试里写死 Windows 路径，Linux CI 就红。**
  `os.path.dirname(r'C:\Apps\x.exe')` 在 Linux 上不把反斜杠当分隔符。
