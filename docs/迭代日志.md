## v0.1.0　能查

**做了什么**

- 本地故障知识库（JSON）+ 关键词匹配查询
- 命令行入口 `main.py`

**为什么从"查"开始**

机房故障有大量重复：同一类问题一年会遇到几十次。
先把「现象 → 原因」沉淀成可检索的条目，比任何花哨功能都实在。

**放弃的方案**

第二版尝试了**决策树逐步诊断**：把每种故障的排查路径做成固定节点树。

做出来、跑通、然后决定放弃：

- 每增加一种故障都要手工写大量节点
- 分支写死，覆盖不了真实故障的多样性
- 新人遇到树里没有的分支就卡住

代码保留在仓库里备查。**这条记录本身就是"方案不是一次做对的"的证明。**

## v0.2.0　能问

**做了什么**

- 接入 DeepSeek API
- 改为**对话式逐层排查**：一次只问一个问题
- Web 界面、流式输出、报修台账

**为什么换成对话**

决策树的问题在于"路径是写死的"，而故障的多样性是无穷的。
大模型不需要预先穷举分支，但它的毛病是**一次给太多** ——
所以加了强约束提示词：一次只问一个问题、不许列清单、不确定就说不确定。

**踩的坑**

- **流式输出里访问 session 报错**：生成器内部拿不到请求上下文。
  改法是把需要的值在生成器外部取好，再传进去。
- **API Key 泄露风险**：Key 一开始写在代码里。改成只从环境变量读，
  并加了启动检查 —— 没有 Key 时服务照样能起，但一问诊就报错，
  这个状态最容易被忽略。

## v0.3.0　能记

**做了什么**

- 教室设备台账（楼栋 / 教室 / 台数）
- 知识库 RAG 检索增强 + 诊断结论自动沉淀
- 跨平台可重入文件锁
- 自动化测试 + GitHub Actions 四平台 CI
- 导出 Excel（教室现状 / 损坏明细 / 故障统计）

**关键判断：检索不引向量库**

知识库只有几十条，引向量库和嵌入模型得不偿失。
最终用字符 3-gram + 同义词归一 + 加权打分，纯 Python 零依赖。

**踩的坑**

1. **异常被静默吞掉，知识库悄悄失效**
   `except Exception: return ""` 把 JSON 解析失败伪装成了"没有知识库"。
   程序照常运行，看起来完全正常。
   **这是最危险的失败模式** —— 崩溃会立刻暴露，静默失败只会让功能少一块。
   修法：补全逗号，并加验证 —— 调用函数确认返回值非空。

2. **同义词缺口**
   用户搜「整间教室断网」检索不到，因为案例正文写的是「无法上网」。
   加分项永远加不上。修法：切分前先扫描原文做同义词归一。

3. **并发写入丢数据**
   「读-改-写」无锁，后写的覆盖先写的。
   修法：进程内 `threading.RLock` + 跨进程文件锁（`fcntl` / `msvcrt`），
   第二层必须可重入，否则内层调用死锁。

4. **文件初始化的「检查-写入」竞态**（只在 Linux 暴露）
   ```
   if not os.path.exists(FILE):        # 多个线程都能通过
       open(FILE, 'w')                 # 'w' 是截断写
   ```
   后到的线程把先到者刚写的内容清空。
   Windows 的加锁与线程调度更慢，恰好错开竞态窗口，本地一直没发现。
   实测 60 轮并发首次创建，**47 轮丢数据**。
   修法：整个检查-创建过程持锁，创建改用 `'x'` 模式。

   > 这类缺陷很容易被当成「测试不稳定」而加个重试糊过去。
   > 判断标准：**结论取决于线程时序的测试，测的不是业务规则。**

## v0.4.0　能管

**做了什么**

- 故障对象区分（电脑 / 教室设施）
- 故障细分类（13 类 + 教室设施 + 其他）
- 反复故障分析
- 课表导入、作息配置、空余教室查询、教师姓名脱敏
- 运行总览：影响上课判定、课程预警、调课建议
- 课表页改为当天矩阵

**关键判断：判断"能不能上课"，不是"坏了几台"**

设备台账里「坏了几台」最容易统计，但它回答不了运维每天要回答的问题。

78 人的课坏 2 台照样能上；教师机坏了，一台不缺也上不了。
所以改成五条判定：整间跳闸 / 整间断网 / 教师机故障 / 教学设备故障 / 座位不够。

**边界是刻意划的**：投影坏了算（没法演示），空调坏了不算（课照样上）。

**踩的坑**

1. **分类器被诊断结论带偏**
   同时匹配「故障现象」和「诊断结论」。结论里有鉴别诊断：
   「换线后显示器正常，问题在主机端」——本意是**排除**显示问题，
   但关键词只看到「显示器」。十八条例题错了三条。
   修法：**只按故障现象判**，现象是值班员写的短句，稳定无干扰。

2. **预警只看今天**
   周日晚上打开系统，今天没课 → 整块空白，
   而明天一早八点的课此刻就受着影响。改成今天 + 明天。

3. **同一间教室重复出十几条预警**
   409 坏了，第 1–12 节每节一条，面板全是同一间教室。
   改成按「教室 + 日期」合并，14 条变 2 条。

4. **连堂课算成 1 节**
   课表里「第 3-4 节」是两条独立记录，按单条算 `p_end - p + 1` 得 1。
   挪过去课就断了。改成按「同一门课、同一老师连续排」往后数。

5. **教师姓名差点泄露**
   最初在前端脱敏 —— 真名仍然在接口 JSON 里，开开发者工具就能看到。
   改成**服务端出口脱敏**，复姓按两个字处理。

**本次交付的缺陷修复**

- 刷新按钮点了没反应（HTML 里有按钮，JS 里从没绑过事件）
- 单间课表弹窗叉号关不掉（绑定只在进过课表页时执行）
- 投影等教学设备故障不产生预警（影响判定里没有这一类）

## v1.0.0　能用

**做了什么**

- 桌面窗口版（pywebview + WebView2）
- exe 打包（文件夹版）
- 界面性能修复
- 设置页（API Key / 数据目录）
- 导出改为落盘 + 显示路径

**为什么要桌面版**

Web 形态每次要先起服务再开浏览器，还留一个控制台窗口。
目标是**换一种启动方式**，不是重写 —— 页面代码一行没改。

**踩的坑**

1. **数据不能打进 exe**
   打包后 `__file__` 指向临时解包目录，数据写进去，程序一关就清空。
   拆成「只读资源」（跟着程序）和「可写数据」（exe 旁边的 `data/`）。

2. **单文件 exe 起不来**
   ```
   [PYI-2580:ERROR] Could not create temporary directory!
   ```
   单文件每次运行要解压自己，被安全软件拦了。改用文件夹版，没有解包步骤。

3. **pywebview 偶发起不来**
   `Failed to resolve Python.Runtime.Loader.Initialize`。
   同一份程序 A 目录能开、B 目录报错，原因未查清。
   加兜底：失败就用 Edge 的 `--app` 模式开窗口。
   兜底里又有坑 —— Edge 已在运行时新进程会交接给已有实例然后立刻退出，
   必须给独立的 `--user-data-dir`。

4. **API Key 读不到**
   用户设过 Key，但 `pythonw` 启动的进程读不到系统环境变量。
   改成三级来源：进程环境变量 → `config.json` → 直接读注册表。
   清除时要写显式 `disabled` 标记，否则注册表兜底又把它找回来。

5. **窗口缩不小**
   「还原尺寸」传成了屏幕尺寸，等于还原后还是整屏。

6. **动画背景 + 满屏背景模糊**
   全站 35 处 `backdrop-filter`，静态背景看不出问题，
   一换成动画背景，这些区域每帧都要重新高斯模糊。改成半透明纯色。

7. **画布不是画得慢，是合成慢**
   实测背景每帧绘制只要 1.0 ms，但开到 60fps 时整页帧率从 145–182 掉到 46–55。
   瓶颈是 DPR=2 时那块 730 万像素的画布层每秒合成 60 次。
   降到 1 倍分辨率（面积 1/4）后恢复。

   > 之前为了省 CPU 把背景限到 20fps，其实是拿「一卡一卡」换了流畅 ——
   > 高刷屏上 20fps 的动画和 180fps 的界面放一起，用户感受就是掉帧。

**本次交付的缺陷修复**

- 桌面窗口里导出 Excel 无反应（winforms 后端没实现 WebView2 的下载事件）
- 课表卡在「读取中」（重写页面时删掉了别人还在用的变量，异常发生在赋值前）
- 下拉框在深色主题下白底白字（要 `color-scheme: dark`）
