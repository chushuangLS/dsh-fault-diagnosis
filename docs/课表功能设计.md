# 课表功能设计

> 本文是课表功能的**实现契约**。写代码前先把它定死，避免边做边改。
> 有异议的地方直接改本文，代码按本文实现。

## 一、为什么要这个功能

真实场景：**教室突然不能用了**（断电、断网、设备损坏），学生站在门口，课马上要开始。

这时最急的不是"这台怎么修"，而是**这节课去哪上**。
所以产品的核心问题只有一个：

> **现在这个时间，哪间教室空着？**

这决定了后面所有设计取舍 —— 这个功能不是"课表管理工具"，
而是**应急调课时的查询工具**。

## 二、功能范围

### 本轮要做

| # | 功能 | 说明 |
|---|---|---|
| 1 | 导入课表 | `.xls` / `.xlsx`，一间教室一个文件，支持一次选多个 |
| 2 | 教室映射 | 课表里的「第一实验楼机房C104」→ 系统里的「实验楼A-104」，自动猜 + 手动确认 |
| 3 | 作息设置 | 学期开始日期（从课表读）、总周数、12 节时间 |
| 4 | 空余课查询 | 选「星期 + 节次 + 周次」→ 哪些教室空着、哪些在上课 |
| 5 | 一键「现在」 | 按当前时间自动算星期/节次/周次 |
| 6 | 座位数筛选 | 调课要装得下学生，可只看 ≥N 座的 |
| 7 | 未导入警示 | 没导课表的教室**不能算空闲**，单独列出 |
| 8 | 单间周课表 | 点空闲/占用卡片 → 看这间教室本周的课 |

### 本轮不做（明确排除，避免范围膨胀）

| 功能 | 为什么不做 |
|---|---|
| 诊断页联动提示 | 先把课表功能本身做稳，联动放下一轮 |
| 整周矩阵视图 | 单间周课表已能满足"这间什么时候空" |
| 就近推荐空教室 | 需要"相邻教室"的定义，需求还没明确 |
| 编辑单条课程 | 课表来自教务系统，手工改会和源头不一致；要改就重新导入 |

## 三、界面

### 3.1 主页面

侧边栏在「日常报备」后新增一项 **课表**。

```
┌──────────────────────────────────────────────────────────────┐
│  课表与空余教室                        [导入课表]  [作息设置]  │
├──────────────────────────────────────────────────────────────┤
│  2026-2027 第 1 学期 · 第 5 周 · 现在 星期二 第 3 节 14:05     │
├──────────────────────────────────────────────────────────────┤
│  星期 [星期二▾]   节次 [第3节▾]   周次 [第5周▾]   [现在] [查询]│
│  座位数 ≥ [___]                                               │
├──────────────────────────────────────────────────────────────┤
│  ┌ 空闲 12 间 ──────────────┐  ┌ 占用中 8 间 ──────────────┐ │
│  │ ○ 实验楼A-201     80 座   │  │ ● 实验楼A-104     80 座   │ │
│  │ ○ 实验楼A-203     80 座   │  │    移动互联网技术           │ │
│  │ …                        │  │    杨沫 · 78 人            │ │
│  └──────────────────────────┘  └───────────────────────────┘ │
│                                                              │
│  ⚠ 2 间未导入课表，无法判断：实验楼B-501、实验楼B-503          │
└──────────────────────────────────────────────────────────────┘
```

**设计决定**

- **进页面自动按"现在"查一次** —— 突发状况下不该让用户先点三下
- **周次默认当前周**，查未来时自己下拉选
- **空闲在左、占用在右** —— 主目标是找空教室
- **占用卡片显示课程 / 教师 / 人数** —— 需要协调时知道是谁的课
- **未导入的教室单独一条警示**，不混进空闲列表 ——
  不知道有没有课就说"空着"，会把人引到正在上课的教室

### 3.2 导入弹窗

```
┌─ 导入课表 ──────────────────────────────────────┐
│  ┌───────────────────────────────────────────┐ │
│  │   拖入或点击选择 .xls / .xlsx（可多选）      │ │
│  └───────────────────────────────────────────┘ │
│  ┌───────────────────────────────────────────┐ │
│  │ C104.xls   课表教室 第一实验楼机房C104      │ │
│  │            座位 80 · 42 门课                │ │
│  │            对应系统教室 [实验楼A▾] [104▾]  │ │
│  ├───────────────────────────────────────────┤ │
│  │ C201.xls   课表教室 第二实验楼机房C201      │ │
│  │            对应系统教室 [未匹配 ⚠] [选择▾] │ │
│  └───────────────────────────────────────────┘ │
│  学期：2026-09-07 起，共 20 周（自动识别）        │
│                              [取消]  [导入 2 个] │
└─────────────────────────────────────────────────┘
```

**交互规则**

- 选文件后**先解析、不落盘**，把结果显示出来让用户确认映射
- 映射自动猜：从课表教室名里取尾部的字母数字（`C104` → `104`），
  在系统教室列表里找同名教室；只有一个匹配就自动选中，多个或没有则留空
- 未匹配的行不允许导入（按钮置灰并说明）
- 同一间教室已导入过 → 行尾提示「将覆盖原有课表」
- 解析失败的文件单独标红并给出原因

### 3.3 作息设置弹窗

```
┌─ 作息设置 ────────────────────────────────────┐
│  学期开始 [2026-09-07]    总周数 [20]           │
│                                                │
│  ┌ 快速生成 ────────────────────────────────┐  │
│  │ 上午第1节 [08:00]  下午第5节 [14:00]      │  │
│  │ 晚上第9节 [19:00]                         │  │
│  │ 单节 [45] 分钟    课间 [10] 分钟          │  │
│  │                          [生成 12 节]     │  │
│  └──────────────────────────────────────────┘  │
│  ┌ 逐节时间（可单独改）─────────────────────┐  │
│  │ 第 1 节   [08:00] – [08:45]               │  │
│  │ …                                         │  │
│  └──────────────────────────────────────────┘  │
│                              [取消]  [保存]    │
└────────────────────────────────────────────────┘
```

**设计决定**

- **快速生成只需 5 个值**：三个起点 + 单节时长 + 课间。
  学校作息本质是「三段 + 固定节奏」，不用填 24 个时间框
- 生成后可逐节微调（实际作息常有不规则：连堂不休息、第 3 节单独排）
- 学期开始日期从课表自动读，这里可改

## 五、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/schedule/summary` | 已导入教室数、课程数、学期、当前第几周第几节 |
| POST | `/api/schedule/parse` | 上传文件**只解析**，返回教室/座位/课程数/学期/建议映射 |
| POST | `/api/schedule/apply` | 确认映射后落盘（可一次多条） |
| GET | `/api/schedule/periods` | 读取作息配置 |
| POST | `/api/schedule/periods` | 保存作息配置 |
| GET | `/api/schedule/query` | `?day=&period=&week=&min_seats=` 返回 free / busy / no_schedule |
| GET | `/api/schedule/room` | `?building=&room=` 单间周课表 |

## 六、边界与异常

| 情况 | 处理 |
|---|---|
| 未配置作息时间 | 顶部提示条 + 「去设置」按钮；"现在"按钮禁用，但手动查询仍可用 |
| 未导入任何课表 | 页面显示引导：先导入课表 |
| 当前超出学期周数（放假） | 顶部提示「第 21 周已超出学期（共 20 周）」，查询仍可用 |
| 文件解析失败 | 该行标红显示原因，不影响其他文件 |
| 教室名解析不出 | 允许手动选映射 |
| 重复导入同一教室 | 整份替换（不合并），导入前提示将覆盖 |
| 课表文件有多张工作表 | 只读第一张（实测样本只有 Sheet0） |

## 八、依赖

`.xls`（OLE2 格式）`openpyxl` 读不了，需要 `xlrd`（纯 Python，体积很小）。
`.xlsx` 仍用已有的 `openpyxl`。

按文件头自动判断实际格式，不看后缀 —— 学校系统导出的后缀经常不准。

## 九、数据脱敏（比赛要求）

### 硬性要求

**作品中不得出现真实教师姓名。**

### 规则

| 数据 | 处理 | 示例 |
|---|---|---|
| 教师姓名 | 只保留姓 + 「老师」 | `杨沫` → `杨老师`、`任雅馨` → `任老师` |
| 教学班编号 | 保留 | `移动互联网技术-0001` |
| 选课人数 | 保留 | `78 人` |
| 教室号 / 设备数 | 保留 | 校内普通信息，演示需要 |
| 学生个人信息 | 不涉及 | 课表文件里只有汇总人数，没有名单 |

### 实现要点

**在后端 API 返回时脱敏，不在前端做。**

前端脱敏的话，真名仍然出现在接口返回的 JSON 里，
打开浏览器开发者工具就能看到 —— 等于没隐藏。

```
data/schedule.json      存真实姓名（已加入 .gitignore，不进仓库）
        ↓  API 层统一转换
前端拿到的 JSON          只有「杨老师」
```

### 转换函数

```python
# 复姓表：欧阳、司马这类不能只取第一个字
_COMPOUND_SURNAMES = ['欧阳', '司马', '上官', '诸葛', '东方', '皇甫',
                      '尉迟', '公孙', '慕容', '长孙', '宇文', '司徒']

def mask_teacher(name):
    """教师姓名脱敏：只保留姓，后面加「老师」"""
    s = (name or '').strip()
    if not s:
        return ''
    for c in _COMPOUND_SURNAMES:
        if s.startswith(c):
            return c + '老师'
    return s[0] + '老师'
```
