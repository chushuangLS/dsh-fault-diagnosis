# 一、课表：为什么没有"查询"按钮

## 问题

教室坏了，最急的不是「这台怎么修」，而是**这节课去哪上**。
学生站在门口，课马上要开始。

## 第一版做错了

第一版是标准的查询式界面：

```
选教学楼 → 选教室 → 选星期 → 选节次 → 点查询
```

**五个动作才能查到一门课。** 日常调课时这会让人抓狂。

更根本的问题是：**它把"找东西"的活推回给了使用者。**
使用者的诉求是"我现在该去哪儿"，不是"请让我先描述清楚我要查什么"。

## 第二版：一屏摊开

```
日期就是一行按钮，点一下就换
整张表是「教室 × 节次」，空格子 = 空闲
点课程格子 → 给调课建议
点空格子   → 看这一节还有哪些教室空着
```

**没有查询按钮。** 打开就是全天的排布。

## 连堂课是最大的坑

课表里「C104 第 3-4 节 移动互联网技术」实际是**两条独立记录**
（第 3-3 节、第 4-4 节）。

所以按单条记录的 `p_end - p + 1` 算连排节数会得 **1** —— 挪过去课就断在中间。

正确做法是往后扫：**同一门课、同一老师连续排了几节**才算连排。

## 调课建议的排序

```
① 同层优先     —— 学生搬电脑最省事（楼层 = 教室编号首位数，C104 → 1 楼）
② 座位最接近   —— 装得下，但别占大教室
③ 连续空闲最多 —— 连堂课要保证整段都空
```

底部同时列出**为什么排除了其他教室**（几间座位不够、几间目标时段有课）。
把取舍摆出来，使用者才知道这个建议靠不靠谱。

## 明确不做的

- **不做一键调课**。教务系统才是权威来源，本系统只给建议。
- **不猜周次**。当前周由后端算，前端只有开学日期和总周数，
  自己推容易在跨学期、假期、时区上出错。
- **未导入课表的教室不显示**。没法判断有没有课，摆在表里只占地方。

## 教师姓名脱敏

课表里有真实教师姓名，作品中不得出现。

**脱敏放在服务端出口**，不是前端 —— 前端做的话，真名仍然在接口 JSON 里，
打开开发者工具就能看到。复姓（欧阳、司马）按两个字处理，
否则会变成「欧老师」。

# 二、运行总览：为什么换掉数据看板

## 看板的问题

旧的数据看板有三个块：

| 块 | 问题 |
|---|---|
| 状态分布饼图 | 记了多少条，看一眼就忘 |
| 教室故障排行 | 排名第一的教室，然后呢？ |
| 故障时段分布 | 知道上午坏得多，然后呢？ |

**它们都是给领导看的统计，不是给运维用的判断。**
看完不知道下一步该干什么。

## 换成一个问题

```
这间教室现在还能不能上课？
```

「坏了几台」回答不了它 —— 78 人的课坏 2 台照样能上，
教师机坏了却一台不缺也上不了。

## 五条判定

| 条件 | 依据 |
|---|---|
| 整间跳闸 | 未解决的设施故障，现象含总闸 / 跳闸 / 停电 / 短路 / 漏电 |
| 整间断网 | 故障对象是教室设施，且提到交换机 / 上联 / 路由器 |
| 教师机故障 | 故障出现在教师机 / 讲台 |
| 教学设备故障 | 故障对象是教室设施，且提到投影 / 幕布 / 音响 / 中控 |
| 座位不够 | 可用台数 < 该节次选课人数 |

**边界是刻意划清的：**

```
投影 / 幕布 / 音响  →  算（电脑不缺也没法演示）
空调 / 灯管        →  不算（课照样上，只是难受）
```

## 预警为什么不只看今天

最早只扫「今天」。结果周日晚上打开系统时，今天没课 → 整块空白，
而明天一早八点的课此刻就受着故障影响，完全看不到。

改成**今天 + 明天**，每条标清「今天 周六」「明天 周一」。

## 为什么按教室合并

409 的交换机坏了，第 1–12 节每节一条预警 —— 面板上 14 条里 5 条是同一间教室，
真正要看的信息（哪几间受影响）被自己的重复淹掉了。

改成按「教室 + 日期」合并，14 条变 2 条：

```
明天 周一  第 1–12 节  第二实验楼-409   12 节课   整间断网   最多 74 人
明天 周一  第 5–6 节   第一实验楼-C110    2 节课   可用 71 台 < 72 人
```

## 反复故障为什么单独列

同一间教室、同一类故障累计 ≥3 次时单列。

反复换内存条可能是插槽氧化，反复报电源故障可能是教室供电不稳 ——
**这类信息在逐条记录里看不出来，必须聚合。**

复发（≥4 次"修好后又出现"）单独标 ⚠，因为复发比高频更指向根因。

## 明确不做

- **不做排名**。哪个教室坏得最多，对运维没有行动价值。
- **不做趋势预测**。数据量不够，画出来的线是假的。
- **两个页面不互相跳转**。各自完整展示 —— 看总览是为了决定去哪，
  看课表是为了决定怎么挪，不需要来回跳。

# 三、共同的判断标准

这两个页面推翻重做时，遵循的是同一条：

> **一个页面如果看完还得再想「那我该干什么」，它就没完成工作。**

统计、图表、排名都不产生行动；
能产生行动的是「这间不能用」「挪到那一间」。
