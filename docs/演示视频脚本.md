# 演示视频脚本 · 机房故障智能诊断助手

> 目标：5–8 分钟，1080p，含 AI 协同过程复现
> 截止：2026-11-07
> 录制者：李一硕

## 一、录制前准备（1 小时）

### 1. 数据准备

录之前先把下面这些**造出来**，否则视频里全是「暂无数据」：

```
□ 报修记录 ≥ 8 条，且至少 1 间教室同一故障累计 3 次（让"反复故障"有内容）
□ 至少 1 间教室有"影响上课"级故障（整间断网 / 整间跳闸 / 教师机）
□ 课表已导入（19 间、1170 条课程）—— 已有
□ 明天有课的那个教室，正好缺几台机器（让预警能生成）
```

### 2. 环境设置

```
□ 分辨率 1920×1080，缩放 100%
□ 关掉所有通知（微信、QQ、系统弹窗）
□ 桌面上不留无关文件（录制会带到）
□ 用 exe 窗口录制，不要用浏览器（地址栏会被看到）
□ 麦克风测试：录 10 秒回放一遍，确认没有电流声
```

### 3. 检查清单（录之前再看一遍）

```
□ 界面上没有真实教师姓名（应该在接口层已脱敏成「杨老师」）
□ 没有出现学校名称
□ 没有出现真实学生姓名
□ API Key 是打码状态（设置弹窗里）
```

## 二、分段时间表

总时长目标：**7 分 50 秒**

---

### 0:00–0:30｜痛点（30 秒）

**画面**

- 微信风格的聊天界面（可以用之前设计的 HTML 动画，或者用文字逐步出现）
- 消息一条条堆叠，越来越快

**旁白**（约 70 字）

> 这是我们机房管理的日常。
> 二十三间教室，一千八百多台电脑，一天几十条这样的消息。
> 而真正在一线值班的，是大一、大二的学生 ——
> 他知道电脑坏了，但他不知道，到底是哪儿坏了。

**制作要点**

- 消息内容要具体：「C104 有台电脑打不开」「408 投影没信号」「老师问明天早八换哪间」
- 最后一句压住，留 1 秒空白再切

---

### 0:30–0:50｜一句话定位（20 秒）

**画面**

- 切到落地页（背景线条在动，三个入口卡片）

**旁白**（约 45 字）

> 所以我做了这个 —— 一个会问诊的机房故障助手。
> 它不教你怎么修。
> 它先帮你判断：是哪坏了，坏了多少。

**制作要点**

- 这句「它不教你怎么修，它先帮你判断」是整片的核心定位，语速放慢
- 鼠标不要动，让画面静 2 秒

---

### 0:50–2:10｜演示一：从「打不开」到一条记录（80 秒）

**画面**

1. 点「开始诊断」→ 输入「电脑开不了机」
2. AI 一问一答（**1.5 倍速**，否则太慢）
3. 得出原因 + 数量
4. 自动跳到报修台账，看到刚生成的记录

**旁白**（约 120 字）

> 值班的学生只需要描述现象。
> 它一次只问一个问题 —— 不会一口气甩给你五条排查步骤。
> 每问完一轮，范围缩小一点。
> 最后给出原因和数量。
>
> 注意，这里问的不是「怎么修」，是「哪儿坏了」。
> 因为值班员的职责是判断和上报，不是拆机箱。
>
> 结论直接落成一条台账记录，不用再手工抄一遍。
> 一条记录可能代表好几台机器，数量会合并。

**制作要点**

- 对话加速到 1.5–2 倍，只保留 3–4 轮问答
- 一定要拍到「记录自动生成」这一刻

---

### 2:10–3:10｜演示二：从一条记录到「明天早八上不了」（60 秒）

**画面**

1. 运行总览 —— 五个 KPI
2. 往下滚到「即将受影响的课」
3. 一条预警特写：第二实验楼-409 · 整间断网 · 明天周一 第 1–12 节

**旁白**（约 90 字）

> 但一条记录只是记录。
> 真正要回答的是另一个问题：
>
> 明天早上八点的课，还上得了吗？
>
> 这一间，交换机坏了，整间断网。
> 明天第一到十二节，十二节课，全都悬着。
> 最高一节七十四人。
>
> 它会顺带算一遍：按现在的可用台数，上不上得了。

**制作要点**

- 409 那条预警要点开/放大，让观众看清「整间断网」和「12 节课」
- 讲到「七十四人」时，鼠标移到人数上

---

### 3:10–4:20｜演示三：调课建议（70 秒）

**画面**

1. 切到课表页 —— 一整天摊开的教室 × 节次矩阵
2. 点 409 那门课 → 调课建议面板弹出
3. 特写候选列表：同层 / 座位 / 连空
4. 再点一个空格子 → 该节的空闲教室

**旁白**（约 100 字）

> 到这里，「上不了」这件事得有人解决。
>
> 这一页不让你先选条件再查询 —— 打开就是一整天的课表，
> 空格子就是空闲。
>
> 点一门课，直接给能挪到哪儿。
> 排序是：同层优先，然后座位数最接近，再看能连续空几节。
> 底部写清楚了为什么排除了其他教室 —— 几间座位不够，几间这个时段有课。
>
> 它不替你决定。它让你三十秒内做完决定。

**制作要点**

- 这一段的鼠标要慢，让观众看清候选列表的三列信息
- 「同层优先」这几个字可以上字幕

---

### 4:20–5:40｜AI 协同过程复现（80 秒）★ 比赛硬要求

**画面**

1. 打开 `docs/AI对话Prompt快照.md`，快速滚动（展示规模：123 条提示词、8 个阶段）
2. 切到一段真实纠错的提交记录
3. 特写：分类器把「电脑打不开」判成「显示故障」的问题

**旁白**（约 130 字）

> 这个项目是我和 AI 一起做的，但「一起做」不等于「让它写」。
>
> 一开始我先定规则：一次只问一个问题、不许编造、不知道就说不知道。
> 这些规则写进提示词，也写进测试。
>
> 但 AI 还是会错。举个例子 ——
>
> 故障分类器一开始把「电脑打不开」判成了「显示故障」。
> 我去查，发现它把「诊断结论」里的鉴别诊断也当成了关键词：
> 「换线后显示器正常，问题在主机端」这句话，让它以为这是显示问题。
> 十八条例题里错了三条。
>
> 改成只按「故障现象」判—— 现象是值班员自己写的短句，稳定、没干扰。

**制作要点**

- **这段是评分的重点**，不要赶
- 截图必须是真实存在的（提交记录、测试文件、Prompt 快照）
- 三个数字一定要说清楚：18 条错 3 条
- 如果时间够，可以再补一句「所以现在有 371 个测试，就是在防这类回退」

---

### 5:40–6:40｜工程质量（60 秒）

**画面**

1. GitHub Actions 四个绿色对勾
2. 终端 `pytest` 跑完：371 passed
3. 双击 exe → 桌面窗口打开（最大化）

**旁白**（约 90 字）

> 一个人做的东西，最容易烂在没人验证上。
>
> 所以这里有三百七十一个自动化测试，
> 四个平台跑 CI —— Windows 和 Ubuntu，各两个 Python 版本。
>
> 还打成了 exe。双击就是一个窗口，不用装 Python，不用开浏览器。
> 打包这一步其实踩了不少坑：数据不能打进 exe，
> 否则程序一关，值班员记的记录就全没了。

**制作要点**

- CI 页面四个绿勾一定要拍到
- exe 打开那一刻，窗口从无到有，效果很好

---

### 6:40–7:20｜设计取舍（40 秒）

**画面**

- 切到文档，或者停在运行总览

**旁白**（约 70 字）

> 最后说两个「砍掉的功能」。
>
> 原来的数据看板有一堆饼图和排行榜，是给领导看的。
> 我全删了，改成「哪些教室现在不能用」——
> 因为运维每天要的不是统计，是决定。
>
> 还有 AI 对话，对老手其实是负担。
> 他心里有数，直接填表更快。AI 是给新人的。

**制作要点**

- 「砍掉的功能」这个说法很加分，说明你有判断
- 语速正常，不要赶

---

### 7:20–7:50｜收尾（30 秒）

**画面**

- 回到落地页，或者停在运行总览
- 最后 3 秒可以淡出

**旁白**（约 60 字）

> 现在它已经在值班室里跑着。
> 十九间教室，一千五百七十六台电脑，一千一百七十条课表，都在里面。
>
> 它解决的不是「怎么修电脑」。
> 是「一个人，怎么管好一个机房」。

**制作要点**

- 最后一句说完，留 2 秒黑屏再结束

## 三、录制顺序建议

**先录屏，后配音。** 理由：画面定了，旁白才好对齐节奏。

```
1. 按时间表逐段录屏（一段一录，不要一口气录完）
   每段录完立刻检查：有没有弹窗、有没有错字、鼠标抖不抖

2. 导入剪辑软件，按时间码拼起来
   对话部分加速到 1.5–2 倍

3. 对着画面配音
   每段单独配，配错只重录那一段

4. 上字幕（关键术语）
   整间断网 / 调课建议 / AI 协同 / 371 个测试
```

## 四、常见翻车点

| 问题 | 避免方法 |
|---|---|
| 超时 | 每段单独计时，加起来超过 8 分钟就砍演示 |
| 画面里出现真实姓名 | 录之前通读一遍，教师名应全是「X老师」 |
| 出现学校名 | 桌面、浏览器书签、窗口标题都检查 |
| 配音有回音 | 在衣柜里录，或者戴耳机麦克风 |
| 鼠标乱晃 | 每次移动前想好落点，移完停 1 秒 |
| 语速太快 | 每分钟 150 字，比平时说话慢一档 |
| 数据是空的 | 开录前一小时把演示数据造好 |

## 五、时间不够时砍哪段

如果录出来超过 8 分钟，按这个顺序砍：

```
① 6:40–7:20 设计取舍（40 秒）—— 最不影响主线
② 5:40–6:40 工程质量（压到 30 秒，只保留 CI 和 exe）
③ 3:10–4:20 调课建议（压到 40 秒）

绝对不能砍：
★ 4:20–5:40 AI 协同过程复现（比赛硬要求）
★ 2:10–3:10 从记录到「上不了」（这是产品的核心价值）
```
