# 运行总览设计

> 取代原「数据看板」。本文是实现的契约，有异议先改本文再改代码。

## 一、为什么替换而不是并存

原「数据看板」有的：6 个 KPI 卡、状态分布饼图、教室故障排行、故障趋势。

新「运行总览」有的：KPI 条、教室状态网格、反复故障、故障类型分布、故障趋势。

**两者重叠严重（KPI、趋势），并存会造成导航困惑和双份维护。**
所以整体替换，不保留旧页面。

### 旧元素去向

| 旧元素 | 去向 |
|---|---|
| 累计故障 / 未报修 / 可自修 / 已报修 / 已解决 / 解决率 | 并入 KPI 条 |
| 处理状态分布（饼图） | **删除** —— KPI 数字已经说完 |
| 故障教室排行（柱状） | **删除** —— 网格上的 ⚠ 已指出哪间有问题 |
| 故障趋势（折线） | 保留，改为「新增 vs 解决」双线 |

## 三、各块规格

### 3.1 KPI 条

| 指标 | 算法 | 点击去 |
|---|---|---|
| 设备可用率 | 正常台数 / 设备总数 | 教室管理，按损坏数降序 |
| 待处理台数 | 未解决记录的数量字段累加 | 报修记录，筛「未解决」 |
| 待处理条数 | 未解决记录条数 | 同上 |
| 反复故障 | 判定为反复的（教室,分类）对数 | 展开反复故障完整列表 |
| 覆盖教室 | 教室台账里的教室数 | 教室管理弹窗 |

### 3.2 今天受影响的课（预警 + 调课建议）

整块回答一个问题：**今天还有哪几节课因为教室故障上不了，该挪到哪。**

「正在受影响」和「今日预警」合并成同一块按时间排序 ——
分开做两块内容重复，而且用户要来回看两处。

#### 判定算法

```
对今天的每一个 (教室, 节次) 组合：
    该教室该节次有课（且当前周在课程周次范围内）？
      否 → 跳过
    该教室有未解决故障？
      否 → 跳过
    ↓ 命中以下任一条即生成一条预警
      · 整体跳闸（未解决的教室设施故障且现象含 总闸/跳闸/没电/停电）
      · 教师机不可用（未解决故障且现象/结论含 教师机/教师电脑/教师用机/讲台/教师端）
      · 可用台数 < 该节次选课人数
```

**同一间教室一天可能有多节命中**，分别列出 ——
每节课的选课人数不同，可能第 1 节够用、第 3 节就超了。

#### 布局

```
┌────────────────────────────────────────────────────────────────────────┐
│  今天受影响的课                          10-17 星期五 · 共 3 节          │
├────────────────────────────────────────────────────────────────────────┤
│  ● 进行中   第 3 节  10:00–10:45   实验楼A-106                          │
│             单片机原理与应用技术（杨老师 · 67 人）                       │
│             整间跳闸 —— 无法上课                                        │
│             → 可调课到  实验楼A-201（80 座）· A-203（80 座）             │
├────────────────────────────────────────────────────────────────────────┤
│  ○ 待开始   第 5 节  14:00–14:45   实验楼A-103     距开始 3 小时 17 分   │
│             移动互联网技术（杨老师 · 78 人）                             │
│             硬盘故障 2 台，可用 76 < 78                                 │
│             → 可调课到  实验楼A-201（80 座）· A-203（80 座）             │
└────────────────────────────────────────────────────────────────────────┘
                                          [展开今天全部 5 节]
```

#### 三种状态

| 标记 | 含义 | 样式 |
|---|---|---|
| ● **进行中** | 这节课正在上，教室有问题 | 红色边框，最醒目 |
| ○ **待开始** | 今天稍后要上，教室有问题 | 橙色，带「距开始 X」 |
| ○ 已结束 | 今天早些时候已上完 | 灰色，默认折进「展开全部」 |

**全天都显示**（不只显示最近 2 小时）——
早上打开就知道今天有几节要调，能提前安排。

#### 可调课教室的挑选

```
座位数 ≥ 该节课选课人数
且 该节次空闲（没人上课）
且有课表数据（未导入课表的教室不能推荐）
按座位数升序 → 取前 3 间
```

**只推荐够坐的最小教室**，不要把 200 座的大教室推荐给 25 人的课。

#### 边界处理（美观优先）

| 情况 | 处理 |
|---|---|
| 超过 5 条 | 只显示前 5 条（进行中优先），其余折成一行「展开今天全部 N 节」 |
| 教室未导入课表 | 块底部一行灰色小字「另有 N 间教室未导入课表，无法预警」，不单独占条目 |
| 一节都没受影响 | **整块隐藏**，不显示"一切正常"之类的空状态 |
| 没有空闲教室可选 | 调课建议位置显示「本时段无空闲教室」，不加图标、不换色 |

原则：**信息完整度让位于版面整洁** —— 宁可少显示，也不要让这一块长长短短、忽高忽低。

数据来源：报修记录 + 课表 + 作息时间。

### 3.3 教室状态网格

网格回答的不是「坏了多少台」，而是 **「这间教室现在还能不能上课」**。
损坏台数只作为小灰字附注，不抢视线。

#### 影响上课的判定

```
影响上课 = 整体跳闸（整间断电）
        或 教师机不可用
        或 有课 且 可用电脑数 < 上课人数
```

| 条件 | 算法 | 数据来源 |
|---|---|---|
| **整体跳闸** | 有未解决的「教室设施」故障，且现象/结论含 总闸、跳闸、没电、停电 | 报修记录 |
| **教师机不可用** | 有未解决的故障，且现象/结论含 教师机、教师电脑、教师用机、讲台、教师端 | 报修记录（关键词识别） |
| **可用 < 上课人数** | `(教室总数 − 未解决电脑故障台数) < 该节次选课人数` | 教室台账 + 报修记录 + 课表 |

**限定条件**：
- 前两条**不限定有没有课** —— 整间跳闸或教师机坏了，任何排在那个时段的课都上不了
- 第三条**只在有课时成立** —— 没课就没有"上课人数"可比

#### 格子形态

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│      103        │    │      104        │    │      106        │
│                 │    │                 │    │                 │
│  ⚠ 影响上课      │    │  ● 正常          │    │  ⚠ 影响上课      │
│                 │    │                 │    │                 │
│  课中 · 78 人    │    │  课中 · 45 人    │    │  没课           │
│  可用 76 台      │    │  坏 2 台         │    │  整间跳闸        │
└─────────────────┘    └─────────────────┘    └─────────────────┘
     红色边框                                    红色边框
```

#### 状态

| 主标记 | 含义 |
|---|---|
| `⚠ 影响上课` + 红边框 | 命中上面任一条件 —— **唯一需要立刻处理的** |
| `● 正常` | 其余全部 |

**底部小灰字**（不抢视线，但信息不丢）：

| 小灰字 | 含义 |
|---|---|
| `坏 N 台` | 有 N 台未解决的电脑故障，但还没到影响上课的程度 |
| `设施故障` | 有教室设施故障 |
| `无课表` | 未导入课表，无法判断上课人数是否够 |
| `课中 · N 人` / `没课` | 当前时段的课表状态 |

**设计理由**：如果做成三种告警等级，眼睛还是要分辨三层颜色；
改成「红色=不能上课，其余全灰」后，扫一眼就知道该去哪一间。
「有坏但不影响」的信息放在小灰字里，需要时能看见。

**折叠规则**：每栋楼最多显示 8 个，超出显示「展开全部 N」。
折叠时**优先显示 ⚠ 影响上课的教室**，其次有损坏的，最后正常的。


### 3.4 反复故障

**判定**：同一教室 + 同一故障分类，累计 **≥ 3 次**（不论修没修好）。

**复发**：其中「已解决后又出现」的次数 **≥ 4 次** 才标 ⚠ 复发。

> 4 是一个很严的门槛 —— 意味着该故障累计至少 5 次。
> 宁可少标，标出来的一定是真问题。

显示：教室、分类、总次数、时间跨度、复发次数。
分页：每页 4 条。

### 3.5 故障类型分布

- 按分类汇总记录条数
- 显示 Top 6，其余合并为「其他 N 类」
- 点击某类 → 跳报修记录并筛该类

### 3.6 近 14 天趋势

- 双线：每日新增 / 每日解决
- 数据不足 7 天时显示「数据积累中」，不画假线

## 四、故障分类

原分类太粗（「开机故障」把电源、内存、硬盘、主板、风扇全包在一起），
做反复故障分析时看不出到底哪个部件在反复坏。细化为 14 类：

| 分类 | 关键词举例 |
|---|---|
| 电源故障 | 电源、供电、插座、开机没反应、不通电 |
| 内存故障 | 内存条、金手指、蓝屏 |
| 存储故障 | 硬盘、SSD、系统盘 |
| 主板故障 | 主板、CMOS、主板接口 |
| 散热故障 | 风扇、积灰、过热、噪音大 |
| 显示故障 | 黑屏、花屏、无信号、显示器、偏色 |
| 网络故障 | 断网、网线、网口、IP、掉线 |
| 外设故障 | 键盘、鼠标、USB、摄像头 |
| 系统故障 | 系统崩溃、重装、驱动、病毒 |
| 投影故障 | 投影仪、投影信号 |
| 音频故障 | 音响、耳机、话筒、没声音 |
| 打印故障 | 打印机、卡纸 |
| 教室设施 | 总闸、空调、交换机、照明 |
| 其他 | 归不进去的 |

每类对应**不同的处理方式**（换电源 ≠ 换内存 ≠ 查供电），所以值得细分。

## 五、联动清单

| 看板元素 | 操作 | 去向 |
|---|---|---|
| KPI 设备可用率 | 点击 | 教室管理，按损坏降序 |
| KPI 待处理台数 / 条数 | 点击 | 报修记录，筛未解决 |
| KPI 反复故障 | 点击 | 展开完整列表 |
| KPI 覆盖教室 | 点击 | 教室管理弹窗 |
| **教室格子主体** | 点击 | **教室详情**（故障视角） |
| **教室格子「课中」** | 点击 | **该教室本周课表** |
| 教室格子（故障+课中） | 视觉 | 红边框 |
| 正在受影响 → 调课建议 | 点击教室名 | 打开空闲教室列表 |
| 反复故障条目 | 点击 | 教室详情 + 筛该分类记录 |
| 故障类型柱子 | 点击 | 报修记录，筛该分类 |
| 趋势图 | 悬停 | 当天新增 / 解决数 |

**为什么教室格子分两个热区**：看到 ⚠ 想知道"坏了什么、修没修"→ 故障详情；
想知道"什么时候能进去修"→ 课表。混在一起反而要多点一次。

## 六、明确不做

| 不做 | 理由 |
|---|---|
| 影响课时 / 平均修复时长 | 汇报指标，运维不看 |
| 教室故障排名 | 排行榜不解决任何决定，网格已给出位置 |
| 故障时段分布 | 能描述现象，但推不出任何行动 |
| 顶部自动生成的一句话结论 | 汇报腔；KPI 和网格本身就是结论 |

## 七、依赖

| 块 | 依赖 |
|---|---|
| 教室网格 | 教室台账 + 报修记录 |
| 正在受影响 / 课中标记 | **课表 + 作息时间** |
| 反复故障 | 报修记录 + 故障分类 |
| 类型分布 | 报修记录 + 故障分类 |
| 趋势 | 报修记录 |

**除「课表」外都已具备。** 课表未完成前，
「正在受影响」和「课中」标记显示「未导入课表」。
