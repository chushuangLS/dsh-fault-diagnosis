# 机房故障智能诊断助手

> 一个面向高校机房运维场景的 AI 故障排查工具。
> 用自然语言描述设备故障，AI 给出分步排查建议与处理方案。

![对话式诊断](docs/screenshots/02-diagnosis.png)

## 项目背景

本项目的需求来自真实的机房运维工作：日常需要管理 **23 间机房教室、约 1840 台计算机设备**，
以及一支 **50 人的学生运维团队**。在实际运维中，高频故障（无法开机、网络中断、
外设失灵等）反复出现，排查过程依赖个人经验，新人上手慢、处理标准不统一。

本项目希望把这类经验沉淀成可检索、可复用的诊断工具，降低对个人经验的依赖。

> **使用情况**：本工具已投入日常机房运维使用，用于故障排查与报修台账管理。
> 下方截图均为实际运行界面。

## 功能特性

- **对话式逐层排查**：一次只问一个问题，根据回答推进，不堆砌大段步骤
- **轻量 RAG**：本地关键词加权检索 Top-3 案例注入提示词，无需向量库
- **知识自动沉淀**：诊断结论自动写回知识库，越用越准
- **四态设备模型**：未报修 / 可自修 / 已报修 / 已解决，区分「坏没坏」与「报没报修」
- **报修台账**：教室维度记录故障，支持数量合并、状态流转、按状态分组
- **故障对象区分**：坏的是电脑还是教室设施（总闸 / 交换机 / 空调），后者不计入损坏台数
- **反复故障分析**：同一教室同一类故障反复出现时单独标出 —— 反复坏同一处，多半是根因不是配件
- **运行总览**：教室状态网格按「还能不能上课」判定，不是「坏了几台」
- **课表与调课**：导入教务课表后一屏摊开当天全部教室 × 节次；点一门课直接给出能挪到哪（按同层 / 座位接近 / 连续空闲排序）
- **一页纸报表**：导出 Excel 给领导看，只回答「现在有多少台能用」
- **AI 不可用时降级**：回退到本地关键词匹配，不至于完全不能用

## 快速开始（10 分钟复现）

### 1. 环境要求

| 项目 | 要求 |
|---|---|
| Python | 3.10 或更高（开发环境为 3.15.0） |
| 依赖库 | `openai`、`flask`（见 `requirements.txt`） |
| API Key | DeepSeek API Key（[申请地址](https://platform.deepseek.com/)） |

检查 Python 版本：

```bash
python --version
```

### 2. 获取代码

```bash
git clone git@github.com:liyishuo1/dsh-fault-diagnosis.git
cd dsh-fault-diagnosis
```

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

> 只跑命令行版（`main.py`）只需 `openai`；
> 跑 Web 版（`app.py`）必须装 `flask`。直接装 `requirements.txt` 两个都有。

### 4. 配置 API Key（重要）

程序从**环境变量**读取 API Key，**不写入代码**（避免泄露）。

**Windows（PowerShell，永久生效）：**

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "你的key", "User")
```

设置后**需要新开一个终端**才能生效。

**临时设置（仅当前终端有效）：**

```powershell
$env:DEEPSEEK_API_KEY = "你的key"
```

**验证是否配置成功：**

```powershell
echo $env:DEEPSEEK_API_KEY
```

能输出你的 key 即表示配置成功。

### 5. 运行

**方式一：一键启动（推荐）**

- **Windows**：双击根目录的 `start.bat`
  （或命令行执行 `.\start.bat`）
- **Linux / macOS**：`./start.sh`

脚本会自动完成这些事，不用记命令：

```
· 检查 Python 与依赖（缺依赖会自动装）
· 从环境变量读取 DEEPSEEK_API_KEY —— 这一步最容易被忘，
  忘了它服务照样能起来，但一问诊就报「请求失败」
· 检查端口是否已被占用（占用则直接打开浏览器，不重复启动）
· 启动后自动打开浏览器
```

常用参数：

```powershell
.\start.bat -Port 5001      # 换端口
.\start.bat -NoBrowser      # 不自动开浏览器
```

**方式一之补充：桌面窗口版（Windows）**

如果不想每次先起服务、再开浏览器，双击根目录的 `desktop.bat`：

```
双击 → 直接弹出一个窗口「机房故障智能诊断助手」
没有地址栏、没有标签页、没有黑窗口
关闭窗口 = 退出程序
```

它用 pywebview 起一个内嵌 WebView2 的原生窗口，
**页面代码一行没改** —— 只是换了个启动方式。

- 打开即**最大化铺满屏幕**，自适应屏幕分辨率；可以还原、拖边框缩小
- 会自动挑一个空闲端口，不和已经开着的 Web 版抢 5000
- 窗口版没有控制台，报错写进 `desktop-error.log`（在程序旁边）
- 需要 `pip install pywebview`

侧边栏底部有一个 **设置** 按钮（齿轮图标），点开可以：

- **查看 / 修改 API Key** —— 当前 key 打码显示，并标明来源
  （进程环境变量 / 配置文件 / Windows 用户环境变量）
- **清除 API Key** —— 会同时屏蔽环境变量和注册表兜底，
  保证「清除」真的生效；重新填一个即可恢复
- **打开数据目录** —— 备份、找 `config.json` 都靠它

这几个接口**只接受来自 127.0.0.1 的请求**。就算有人把服务开到局域网，
别人也改不了你的 Key、也弹不出你机器上的窗口。
**打成 exe（不用装 Python）**

```bash
tools\build_exe.bat
```

产物在 `dist\机房故障智能诊断助手\`，**整个文件夹一起拷走**，双击里面的 exe 即可。

构建脚本会把当前 `data\` 下的真实数据一并拷进产物，
所以打出来的包**打开就有内容**（教室台账、报修记录、课表全在）。
不想带数据的话，打完删掉产物里的 `data\` 即可 —— 首次启动会自动铺一套空骨架。
