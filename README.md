# 机房故障智能诊断助手

> 一个面向高校机房运维场景的 AI 故障排查工具。
> 用自然语言描述设备故障，AI 给出分步排查建议与处理方案。

## 项目背景

本项目的需求来自真实的机房运维工作：日常需要管理 **23 间机房教室、约 1840 台计算机设备**，
以及一支 **50 人的学生运维团队**。在实际运维中，高频故障（无法开机、网络中断、
外设失灵等）反复出现，排查过程依赖个人经验，新人上手慢、处理标准不统一。

本项目希望把这类经验沉淀成可检索、可复用的诊断工具，降低对个人经验的依赖。

## 功能特性

- **自然语言输入**：不需要记忆关键词，直接描述现象即可
- **分步排查引导**：每一步说明「做什么」和「看什么现象」
- **分支判断**：根据排查结果给出不同的下一步
- **结合本地知识库**：AI 回答时参考本校机房的历史案例
- **自动降级**：AI 不可用时，回退到本地关键词匹配

## 快速开始（10 分钟复现）

### 1. 环境要求

| 项目 | 要求 |
|---|---|
| Python | 3.10 或更高（开发环境为 3.15.0） |
| 依赖库 | `openai` |
| API Key | DeepSeek API Key（[申请地址](https://platform.deepseek.com/)） |

检查 Python 版本：

```bash
python --version
```

### 2. 获取代码

```bash
git clone git@github.com:liyishuo1/dsh-fault-diagnosis.git
cd dsh-fault-diagnosis
```

### 3. 安装依赖

```bash
pip install openai
```

### 4. 配置 API Key（重要）

程序从**环境变量**读取 API Key，**不写入代码**（避免泄露）。

**Windows（PowerShell，永久生效）：**

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "你的key", "User")
```

设置后**需要新开一个终端**才能生效。

**临时设置（仅当前终端有效）：**

```powershell
$env:DEEPSEEK_API_KEY = "你的key"
```

**验证是否配置成功：**

```powershell
echo $env:DEEPSEEK_API_KEY
```

能输出你的 key 即表示配置成功。

### 5. 运行

```bash
cd src
python main.py
```

### 6. 使用示例

程序启动后，直接用自然语言描述故障：

```
=======================================================
  机房故障智能诊断助手  v0.3.0
=======================================================

已加载 2 条故障案例（作为 AI 参考资料）
请用自然语言描述故障现象，AI 将给出诊断建议
输入 q 退出

故障描述：老师电脑连投影仪没反应，屏幕黑的

正在分析，请稍候...

=======================================================
【AI 诊断建议】
=======================================================

**故障类别：** 显示信号传输链路问题

**先确认两个问题：**
1. 老师电脑自己的屏幕有画面吗？
2. 投影仪有没有亮灯/显示"无信号"？

**排查步骤：**

**第 1 步：看投影仪画面**
- 显示"无信号" → 投影仪正常，是信号没进来，继续第 2 步
- 完全黑 → 投影仪本身问题，跳到第 5 步

**第 2 步：检查视频线两端**
- 插紧后画面出来 → 线松了，问题解决

...
```

输入 `q` 退出程序。

## 故障知识库格式

知识库为 JSON 格式，AI 回答时会参考这些案例。

| 字段 | 说明 |
|---|---|
| `id` | 案例编号，如 `PC-001` |
| `category` | 故障分类，如"开机故障" |
| `symptom` | 现象描述 |
| `causes` | 可能原因列表 |
| `steps` | 排查步骤列表 |
| `severity` | 严重程度 |
| `est_time` | 预计处理耗时 |

示例：

```json
{
  "id": "PC-001",
  "category": "开机故障",
  "symptom": "按开机键没有任何反应，指示灯不亮，风扇不转",
  "causes": ["电源线未插紧或插座无电", "电源开关被关闭"],
  "steps": [
    "检查电源线两端是否插紧",
    "换一个插座测试"
  ],
  "severity": "高",
  "est_time": "5-10 分钟"
}
```

## 技术实现说明

### AI 提示词设计

系统提示词约束了 AI 的角色和输出格式：

```
你是一名高校机房的资深运维工程师，负责管理机房设备和排查故障。

要求：
1. 先用一句话判断故障的大致类别
2. 列出可能的原因（按可能性从高到低排序）
3. 给出具体排查步骤，每步说明"做什么"和"看什么现象"
4. 说明如何判断原因
5. 给出处理建议（自己修 / 报修）
```

### 知识库作为上下文

程序会把 `fault_cases.json` 中的案例整理后，作为 system 消息传给 AI，
使回答更贴合本校机房的实际情况。

### 安全设计

- API Key 只从环境变量读取，代码中无明文
- `.gitignore` 排除 `.env` 等敏感文件
- 参数 `temperature=0.3`，让回答更稳定专业
